# BI 与角色权限验收记录

更新于 2026-09-12。此记录补充本日早期审计，不把页面重构、测试通过等同于全部业务对账完成。

## 页面与业务路径

- 总览保留销售额、回款额、待回款、回款率，成本及结余仍在总览；确实缺少成本事实的部分保留局部“样例”标识。
- 图表连续布局，专题按业务问题组织。全国销售排行可下钻城市和销售；选中单个销售时使用个人趋势与回款进度，不显示“筛选后全国第一”的排名。
- 城市商品分析使用 ERP 品牌、分类、商品与 SKU。分类父级查询覆盖其后代，日期和商品范围随明细下钻保留。
- 报表默认不分摊混合订单回款；手动分摊明确显示分摊金额及归属状态。业务字段默认全选，Excel 不展示内部关联编号，金额保留两位，单位使用字典名称。
- 经营目标、运营跟进及来源复核采用持久化接口；普通角色必须获得相应写权限。没有真实目标时不伪造目标或完成率。
- 角色与数据范围分开控制，前端不能通过修改筛选参数扩大服务端员工或城市范围。

## 权限落库

入口：`/#/system-admin/roles`。

- 后端返回 `permissionMode=ALL_ENTITLED` 的系统管理员默认获得本租户当前已订阅、启用应用的有效权限，不获得平台或其他租户权限。
- 普通角色通过页面搜索、勾选、保存显式授权；父子菜单联动。管理员权限只读，不能被误删成部分权限。
- V86、V87 已通过 IAM 正常启动迁移应用到共享 DEV，未修改已执行的迁移。
- 补齐三个 BI 写权限的管理员授权，恢复当前订单服务所需 `order:write`，修正订单读取和 ERP 采购库存权限父级。
- 已核对当前 64 个非占位页面路由的活动资源与页面声明的读取权限；无缺失菜单配置、无失效父级。
- 数据库读回确认订单写权限活动有效、三个 BI 写权限均已有管理员授权；普通角色授权基线未改变，既有租户隐藏菜单配置保留。
- 追加全后端业务权限核查，发现订货宝读写权限挂在停用旧应用。V87 将原资源迁至当前供应链同步中心，保留原套餐及普通角色授权，旧应用不恢复。数据库读回管理员共 81 项有效权限，包含业务写权限；服务身份专用的内部投影、租约和跨租户发现接口不作为人工权限发放。
- 管理员未来新增权限通过当前有效资源视图计算；持久化基线中历史失效资源不会因此重新生效。

## 不得混淆的边界

- 当前普通角色没有真实业务配置样本。普通角色新增/保存/撤销、越权与只读行为有自动化覆盖；没有为验收擅自创建角色或改变人员权限。
- 当前线上飞书会继续变化。文件版本复核保存不可变证据，但旧文件匹配不能证明“此刻在线表格完全一致”。直接在线只读抓取尚未形成完整公共接口，不能把它标为已完成。
- 采购库存有真实数据，但没有可靠城市仓库归属或包装换算时，不推算城市库存、不把不同单位直接相加。
- 不以样例成本推导实际利润，不编造个人工资、绩效目标或客户跟进记录。已确认退款而排除的零数量订单不自动补录。
- 未宣称完成全部角色实号权限交叉验证或完整 WCAG 验收。
