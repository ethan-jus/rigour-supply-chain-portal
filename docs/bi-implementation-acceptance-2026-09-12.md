## 订货报批场景

需求：运营导出各城市方便面等品类的销量、销售额及对应回款，向老板申请厂家订货付款。

- BI 付款事实目前仅关联订单，无商品行核销关联。
- 订单应收可能包含整单优惠，不能用整单回款充当方便面回款，也不能假定行金额之和等于应收。
- 总览、城市经营及商品销售的“城市商品报表”入口提供真正的 `.xlsx` 文件。新增城市经营汇总、城市单品月报两种业务主表，加城市分类、商品SKU、订单核对和统计口径共五个工作表；核对明细模式保留原四表。
- 业务字段默认全选，可分别选择业务主表及三个明细表的列。调整日期、城市、销售、客户类型、分类、来源后以本次实际查询为准；字段选择不改变返回行范围，不随分页少导数据。业务字段不包含内部 ID、城市编码或分类编码。
- 各图表明细导出同样改为 Excel，可勾选表头；按当前明细筛选导出全部记录。金额统一四舍五入保留两位，城市商品报表内部仍保留原始精度用于汇总和核对；不得先逐行舍入后再求总计。
- 默认 `EXACT_ONLY`：混合商品无法确定的归属保留待确认；`PROPORTIONAL` 必须明示按整单商品金额比例分摊，分类筛选不能改变分母。
- 非正常订单、退款、负数、缺行及分母问题不自动分摊；未确认金额不得当零。
- 单位按真实业务字典转换后分别统计，不将箱、桶、瓶等相加，数量去除无意义尾零；不导出截断结果。缺单位、缺分类如实保留，不从商品名称猜分类或折箱。
- 用户已确认“仍默认不分摊，手动选择分摊”。本记录不代表报批或付款获批。

## 业务报表扩展

- 城市经营汇总：动态 ERP 品类列、商品销售额、去重订单数、去重下单客户数、当前客户档案数及原单位数量；全部分类时补充每订单只计算一次的应收、累计回款、未回款及差额。筛选分类时隐藏整单资金列，避免被误认为该分类回款。
- 城市单品月报：按筛选范围生成北京时间月份列，保留城市、商品、规格和原单位；每月及期间合计展示数量、销售、已归属回款、其中分摊回款和核对状态，提供城市小计及筛选范围合计。不限定方便面或固定两个月。
- 月份来自后端订单事实聚合，不将期间总额平摊到各月。缺月度合同、重复月度行或与期间汇总不符时阻止导出。
- 客户档案取 BI 当前客户维表，受城市、销售及客户类型筛选，不受订单日期、分类、来源影响；不是历史期末客户数。下单客户按订单事实在当前范围独立去重，不能累加城市客户数作为全国客户数。
- 姓名、规格使用 BI 事实快照；单位使用业务字典，页面及 Excel 均使用两位金额。月报回款是所选月份订单的累计回款，并非当月现金流入。
- 参考样表的“1箱=12桶”不是所有商品的通用规则。没有经核验的结构化包装换算时，只展示原单位；本轮不伪造箱数或采购建议量。

## 尚需单独闭环

1. HR 绩效当前是预留页，无目标录入、发布到 BI 的现成接口；本轮未伪造配置入口。
2. 成本和活动样例只用于结构演示，不能作为实际盈亏或报批付款依据。
3. 当前 BI 读权限是租户级权限，未按登录销售/城市自动收窄数据范围。若将读权限发给普通销售，必须先确认可见性政策并补服务端授权范围；页面筛选不是权限边界。
4. 当前内部 BI 与用户样表使用的订货宝导出覆盖不同：该范围当前 BI 方便面仅两种商品，参考表为四种；不能声称已与订货宝全量数据对齐。未分类商品、缺失单位需要在源数据/同步映射中核对，不在报表端猜测补齐。
5. 全部源业务对账、共享 DEV、细粒度权限，以及新业务主表移动端和完整可访问性验收仍未闭环。已有固定测试页手机验收不等于新主表全部通过。
6. 后续采购报批建议补齐经核验的包装换算、可用库存、在途、采购价、供应商及动销周期，再计算建议订货量；本轮没有自动生成采购单或付款申请，也没有保存个人报表模板配置。

本轮没有提交或推送，没有执行成本导入、全量同步、迁移或业务数据写入。原有无关工作区修改保留。
