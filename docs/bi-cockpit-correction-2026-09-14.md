# BI 驾驶舱编排与业务口径补全

日期：2026-09-14。本文件记录本轮实现；9月11日旧验收文件中的成本比例、目标页面、未完成事项是历史状态，不能直接作为当前结论。

## 页面编排

- 总览默认保留销售额、回款额、待回款、回款率四项。主分析列为销售趋势、完整宽度成本瀑布及成本/结余读数；右列为回款和经营跟进。城市商品、全国榜、费用构成在同页分析页签中查看。
- 销售默认先显示完整全国榜及每人的销售额，保留搜索、指标切换与分页；下方再用同刻度的前六人员月度折线小图观察变化。侧列保留回款、逾期跟进及目标。前六不是全部销售人员。
- 城市默认用经营矩阵比较销售、累计回款、待回款和回款率，金额与百分比使用独立刻度。单城市切换到趋势；团队、商品客户在分析页签内查看。
- 商品主列为城市品类交叉分析和商品贡献，侧列分类/品牌构成。分类、品牌、商品、SKU不混为一个维度。明细及城市商品Excel保留原接口与筛选。
- 库存按单位分析需求、供给和可售天数；真实库存未返回时不模拟库存，仅显示真实日均销售需求。零/少量数据不撑成大色块。
- 成本、人力、活动、客户、回款、毛利等专题仍保留业务范围，改为主分析/辅助监测和本地分析页签；不是将全部图表追加到一长页。

分组切换保留本地搜索、分页和成本分组。业务筛选、身份权限、图表口径或数据快照变化时清空旧缓存；最多缓存6个分析工作区。页签具有真实tabpanel关联及方向键、Home、End操作。库存单位在各分析页签都可切换。

## 业务口径入口

顶部“口径说明”可搜索当前专题全部指标和图表。每个主指标、每张图旁的信息按钮直接聚焦对应说明；SQL/源表技术说明仍放在“源指标定义”，不占看板主画布。

说明实现：`src/views/supply-chain/bi/cockpit-methodology.ts`；展示组件：`components/CockpitMetricGuide.vue`。覆盖所有12种专题模型的主指标、图形及优先跟进规则，新增模型必须通过说明覆盖测试。

核心区别：

| 业务问题 | 已明确的口径 |
| --- | --- |
| 为什么展示这六人 | 当前权限/期间/筛选内销售额降序，排除未归属销售，同额稳定排序，最多6人；不是综合绩效，数字6是展示数量限制 |
| 全国榜如何排名 | 可按销售额或订单累计回款；同额并列，如1、1、3；筛选和数据权限仍有效 |
| 回款率 | 同批订单累计已收合计 / 同批订单应收合计，不平均各销售或城市的比率；非正分母不计算，超额保留 |
| 实际到账 | 按回款发生日期统计；与按订单日期选出的累计已收不同，不能混作一个指标 |
| 前期比较 | 相邻等长订单期间，不自动称为自然月环比/同比；零基数及无前期订单单独处理 |
| 客户与复购 | 当前有效客户存量与期间下单客户区分；复购指期间至少2笔订单；跨城市客户不直接相加 |
| 客户ABC、跟进 | 按累计销售贡献分层；满30天未下单或从未下单属于跟进范围，不等于真实流失；优先名单不是全量客户 |
| 逾期与账龄 | 逾期金额按到期时刻，账龄按北京时间日期差；跨日条件、默认账期和缺失到期日处理公开 |
| 商品与毛利 | 订单行销售额、退款分配、净收入、采购参考成本及金额覆盖率分别说明；参考毛利非财务净利润 |
| 成本及结余 | 已入账总额不拆成虚构分项；仅缺失城市费用用样例。样例城市、日费用、销售比例及计算金额可逐项查看 |
| 库存与采购 | 同单位才相加；采购发货为期间流量、留存为当前存量；补货用30天覆盖模型，无销量和无库存快照分别处理 |
| 报表分摊 | 混单回款默认不分摊；用户选择比例分摊时标注。退款分配与回款分摊是不同规则 |
| 样例活动 | 费用产出比不是利润ROI，活动转化按合计分子/分母；独立样例不合入真实销售 |

说明中的当前金额、人员姓名和样例费用计算从当前模型读取，不另造用于展示的“真实数据”。共用业务规则的指标也保留各自首行公式，例如逾期客户是去重人数，平均逾期天数是订单天数算术平均，不以逾期金额公式替代。金额使用原值计算，万元仅为显示单位；页面金额/明细/Excel保留两位。比例按页面现有精度显示，计算不使用先取整的万元数。

- 商品分类常驻筛选行，实页返回ERP全部13个分类；SKU分析入口改为业务标签“规格/型号”。按SKU仍需进入销量与回款报表核查原单位及归属，不拆分未区分的H/M。
- 城市品类SQL不再排除缺分类关联的有效订单行；UNKNOWN分类在前五图形范围外也额外保留，可带城市进入待核对订单。仍以权限和查询条件为边界。
- 去掉人员月份300条及SKU80条的静默截断；UNKNOWN不再用跨记录MAX拼出不存在的商品名称/规格，同一SKU的多个名称或规格快照会提示冲突。
- Integration商品匹配不再将品牌/规格片段注册成商品身份；只匹配完整引用或明确编码，同名多SKU的有歧义别名不再任选首个。此项防止后续导入误绑，不会自动重写历史订单。
