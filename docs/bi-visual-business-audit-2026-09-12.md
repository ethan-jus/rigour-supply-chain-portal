# BI 可视化与业务链路复核

## 本轮基线

- ERP、Order、CRM、字典、HR 均按已有真实业务数据处理。“BI 尚未关联”不等于“源系统不支持”。不得以样例替代已有业务事实。
- 成本、活动中确实缺少的事实项才保留独立样例标识；采购参考成本不等于实际经营成本。
- 总览保留销售额、回款额、待回款、回款率，以及成本、经营结余。保留城市、销售、客户、商品专题和既有 Excel 导出。
- 不做城市/库存散点图，不做回款率横向进度榜，不使用大色块矩形树图，不增加角色说明卡片。

## 已实施

| 业务问题 | 可视化与动作 |
| --- | --- |
| 销售、收款如何变化 | 折线趋势；月度销售 Top6 从多组柱改成趋势线，数据点保留月份和销售归属 |
| 回款到了什么程度 | 单个回款仪表与已收/待收金额；不截断超过 100% 的真实值，不把待收当逾期 |
| 哪些城市销售多、收款慢 | 同一城市已收/待收金额对比，保留销售、客户下钻；不使用散点 |
| 销售额被哪些成本消耗 | 销售到货、人、场再到结余的瀑布；三层总额的分项仍在明细中可核对 |
| 货、人、场如何构成 | 紧凑双层成本结构图；内层维度、外层费用；点击分别查看对应维度或费用，不再用大矩形块 |
| 哪些商品值得重点关注 | 商品、SKU、品牌使用金额与累计贡献组合图；少量分类保留占比图，不强行套一种图 |
| 每个城市主要销售哪些品类 | 真实城市 × ERP 分类销售金额矩阵，商品页也加载既有运营分析接口 |
| SKU 参考采购成本多少 | 成本页新增 BI 已有的 ERP 采购参考成本图和覆盖率明细；不重复计入经营总成本 |
| 库存先看什么 | 采购/发货/留存、可用/在途/建议补货、可售天数分别用单位一致的矩阵；无日销量为“未计算”，不是 0 天 |
| 哪些库存异常需要处理 | 风险类型 × 等级矩阵；风险数是接口返回风险项数量，不冒充全部 SKU 数 |

原有全国销售人员业绩排行、风险对象明细、订货报批报表继续保留。排行榜适合精确比较，不为增加图形种类而改成难读的面积图。

总览主区固定为趋势、回款进度、成本盈亏、成本结构四个图，优先跟进置于其后；城市与商品、全国销售业绩切换展示，不再把所有分析平铺成长页。切换分析不重新请求或改变业务筛选。

### 已修复的业务偏差

1. 品牌下钻原先传 `brandName`，ERP 商品页不读取，实际打开全部商品。现改用 `brandId`，补品牌筛选、选中名称展示、换条件回第一页、清空筛选。未绑定品牌 ID 时明确提示，不退化为全量。
2. BI 品牌聚合中的分类来自 `MAX(category)`，不能把它当成品牌唯一分类。品牌明细移除这项错误展示；品牌、分类保持独立维度。
3. 商品聚合不含单位，移除该层直接累加的数量列。单位数量仍从既有城市商品报表核对，采购库存按同单位统计。
4. 金额、累计占比、缺失值分别处理；负调整不转换成正面积，零总额不伪造百分比。缺失库存天数用独立灰色格渲染。

## 已核对的真实业务能力

| 源服务 | 已有事实与关联 | BI 需要遵守的边界 |
| --- | --- | --- |
| ERP | 商品、分类、品牌、SKU 规格、单位、采购参考价、仓库及库存相关接口 | 品牌可跨分类；起订量/倍数不是箱桶换算；参考价估算不能冒充实际采购成本 |
| Order | 订单与商品行、客户、责任员工、应收/已收/未收及回款事实 | 订单金额与商品行金额分开；混单回款默认不分摊，手动比例分摊明确标注 |
| CRM | 客户/门店、销售关联，包含员工编码与名称 | 当前客户归属与历史订单责任人不是同一时间口径，不能靠同名强行合并 |
| HR | 员工身份、组织、城市、在离职等员工档案 | 有成交销售人数不等于在岗人数；人均产出需员工范围和有效任职期，工资只显示授权汇总 |
| 字典 | 服务端有效字典、商品单位等业务标签 | 优先真实字典；未知值保留来源值，不臆造中文或单位换算 |
| 销售工作 | 工作日、打卡、有效工作时长、拜访客户/门店、意向、审核与管理汇总 | 临时打卡人员 ID 与 HR/CRM 标识需映射；没有排班时不推断旷工；拜访不直接证明订单成交 |

源码核对入口：Portal 的 `src/api/core/erp-product.ts`、`erp-internal.ts`、`order-sales.ts`、`bi.ts`、`src/utils/business-dictionary.ts`；Platform 的 `SupplyDashboardQueryMapper.java`、`SalesAssignmentView.java`、`SalesWorkApiModels.java`、`SalesWorkManagementApiModels.java` 及 HR 员工 API。

## 仍需完成的关联工作

这些是看板集成缺口，不是源系统没有数据，本轮未声称已完成：

1. 城市 × 品牌 × 商品/SKU 的多维交叉分析及品牌报表过滤。当前已有品牌与 SKU 销售汇总、城市 × 分类交叉，以及城市单品月报；不能从分类汇总反推出品牌或 SKU。
2. HR 员工、CRM 责任销售、打卡/拜访人员与 BI 业绩的稳定标识映射和按任职期统计。需要通过领域接口或 BI 投影接入，不在前端拼接人名。
3. “拜访后 N 日下单”的统计窗口、去重、责任归属与数据权限。即使数据可关联，也只能说明时间关联，不能称为拜访导致成交。
4. 真实成本费用分项、期间与城市归属的对账；保留已入账真实总额，不按演示比例拆分。ERP 参考采购价不与完整经营成本重复相加。
5. 源业务数据与 BI 快照对账、历史归属和权限范围的完整验收。

## 参考与设计取舍

- [Power BI 官方驾驶舱设计原则](https://learn.microsoft.com/en-us/power-bi/create-reports/service-dashboards-design-tips)：重要信息前置，减少无关细节，统一尺度与颜色，不为多样性而多样化。
- [Tableau 官方图表选择](https://help.tableau.com/current/pro/desktop/en-us/what_chart_example.htm)：先明确问题与数据性质，再选择图形。
- [Power BI 销售与营销示例](https://learn.microsoft.com/en-us/power-bi/create-reports/sample-sales-and-marketing)：采用概览、时间变化、区域/品类拆解的分析顺序；不复制其卡片或树图外观。
- [Power BI 小多图](https://learn.microsoft.com/en-us/power-bi/visuals/power-bi-visualization-small-multiples)：可用于后续城市趋势并排比较，但必须先有对应城市时间序列，不从城市总数生成假趋势。
- 用户提供的[财务能力分析看板参考图](https://pica.zhimg.com/v2-80c39cb88ac6a72a6a9db1a2b2768080_r.jpg)已在浏览器查看。借鉴集中主视图、辅助指标与下方专题分析的层次；不照搬未核实的财务指标、装饰性进度条及大表。

## 当前阶段方案选择

比较基于官方资料和现有源码，不是厂商产品的付费试点、性能实测或价格评估。

| 参照 | 已核实优势 | 对本项目的判断 |
| --- | --- | --- |
| Power BI | 总览/专题、交互分析、嵌入式报表 | 信息组织值得借鉴；整套接入需处理授权、身份与语义模型。不是换几个图即可替代原 BI |
| FineBI | 业务自助、多维联动、仪表板跳转、行列权限 | 最适合作为业务分析交互参照；现阶段不必先引入完整自助平台 |
| Tableau | 探索式可视分析、嵌入、单点登录与权限接口 | 适合进一步开放分析师自由探索；当前优先把固定经营问题做可靠 |
| DataV | 低代码看板、可视化大屏、地理及二三维组件 | 可作为展示端参考，但展示能力本身不能补齐订单回款归属和运营动作 |

**推荐：保留现有 Vue/ECharts 与 BI 服务，建设嵌入业务系统的经营决策驾驶舱，以 FineBI 式联动分析作为主要产品参照。**

选择依据：已有领域系统、BI 投影、登录权限和业务详情页；近期主需求是固定经营监控、城市销售商品分析与订货报批。应复用它们，先完成统一指标、准确下钻、业务动作与验收，而非并行建立第二套数据模型和权限链路。

这不意味着自研必然更便宜。若后续主要需求变成大量用户自由拖拽建报表，应启动 FineBI/Power BI 的真实数据试点，并比较授权、身份对接、数据权限、开发运维的总成本。

确定的产品分层：经营监控总览；城市/商品/销售/客户/库存/成本专题；订单、客户、SKU 与 Excel 核对明细。角色通过权限、默认范围和入口服务，不在总览罗列角色卡片。视觉上用浅色、克制配色、紧凑指标带和明确的主分析区，图形按业务关系选择，不套同一种图。

官方依据：[FineBI 分析功能](https://www.finebi.com/product/functions/analysis)、[FineBI 数据与权限](https://www.finebi.com/solutions/dp)、[Power BI 嵌入说明](https://learn.microsoft.com/en-us/power-bi/developer/embedded/embedded-analytics-power-bi)、[Tableau 嵌入分析](https://www.tableau.com/en-gb/products/embedded-analytics)、[DataV 产品文档](https://help.aliyun.com/zh/datav/)。
