# 公海门店列表重新设计验收

## 设计判断

- 主技能 ui-ux-pro-max；frontend-design 用于信息优先级；design-taste-frontend 使用 app-screen 流程。
- 选择 Framed sheet，seed 1874914582；保留现有品牌与全局字体，没有重抽。保留用户明确要求的深色表头及浅底表头带，优先于技能的灰色无底表头建议；不改全站导航结构。
- 页面首先回答：这是什么门店、在哪里、能否查看位置及认领。默认显示门店名称、POI、类型、省份、市、区县、地址、门店标签、操作。
- 表格对象来自现有 StoreRow，接口与授权范围保持原状；POI 直接显示 primaryPoi，省市县取已存在的独立字段，不根据地址文字推断。定位使用门店自有坐标，POI 缺失不等于不能定位。
- 名称独占 280px，POI 150px，类型 110px，省 132px，市/县各116px，地址至少300px，标签174px，操作90px；默认总最小宽度1468px。地址承担大屏剩余宽度，小屏表格内部横向滚动，桌面固定名称和操作；窄屏解除固定，避免挡住全部内容。
- 字体延用显示设置，正文/表头默认14px，表头600字重；主要文字#1f2329，正文#303133，辅助文字#606266；白色表面、浅灰蓝表头、品牌蓝定位图标。
- 标签单独一列，名称不再夹带标签/地址；保留合作状态和价值等级的原有业务含义。日期类字段默认关闭，可通过列设置开启；提供恢复默认列。
- 认领阻断原因保留在可聚焦按钮包装的提示/辅助名称及可选状态列，避免每行重复长说明；没有绕过授权或变更业务数据。

## 最终视觉复核

1. 主体是门店清单，名称、POI和各级地理信息可沿列扫描；去掉默认空日期列及重复长状态。
2. 表头与内容边缘一致；名称固定宽度，避免此前过宽的混合信息列。大屏地址列仍吸收剩余宽度，以容纳长地址。
3. 品牌蓝只用于现有操作、定位与交互，名称和辅助字段保持足够对比度；无新增装饰卡片。
4. 总数/分页继续由服务端结果驱动；地图明确显示当前页数量，未虚构全量落点。
5. 无POI显示未关联，缺坐标明确位置待完善，按钮保持业务限制。
6. 名称与标签拆开；地址自然换行，未截断重要地址；定位图标与文本无重叠。
7. 窄屏为完整数据表内部横向滚动，主要用于桌面运营；不是重新设计移动端卡片。移动导航保持原系统行为。
