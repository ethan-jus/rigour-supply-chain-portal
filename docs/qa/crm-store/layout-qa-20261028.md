# CRM 紧凑布局与后台公共样式清理 · 2026-10-28

## 目标与设计依据

本轮处理公海、我的客户、合作客户、商家库共用的页面布局；同时按用户追加要求，清理后台前端文档和公共 CSS 中不合理的强制样式。业务权限、数据口径、迁移与接口契约不变。

采用 karpathy-guidelines、ui-ux-pro-max、frontend-design、design-taste-frontend 的应用界面流程。沿用项目语义色与中文系统字体；应用方向为 Framed sheet，seed 593329022，无重抽。原技能的外壳重建、无色按钮等建议不覆盖当前用户选定的后台样式。

- 页面问题：当前授权范围内，哪些门店需要认领、跟进或查看位置？
- 主体：门店列表或地图。保留门店名称、合作/价值标签、定位图标、地区、最近拜访/成交、认领状态。
- 数据：当前 DEV 公海 11 家；显示接口返回总数，不把地图本页位置数冒充全国覆盖量。
- 用户：销售、主管、管理员。最常用动作是查询、查看详情和定位。
- 特征：全国/城市范围提示，独立的合作与价值标签，列表定位后切地图并聚焦原门店。
- 色彩角色：背景 #f6f8fb，内容 #ffffff，正文 #0f172a，次级文字 #64748b，操作 #2563eb，边界 #e2e8f0。颜色通过现有主题/Token 使用。
- 字体：系统中文字体；标题、门店名称、辅助地址形成层级；数值采用 tabular-nums。
- 间距和尺寸是当前实现值，随数据密度、交互与视口调整，不构成后续设计的硬性约束。

## 实现

- 复用订单 `OrderRegisterFilterCard`：宽度不足时默认折叠到一行，查询/重置保持第一行右端；取消 CRM 筛选卡片背景、外框及显式标签，保留 aria-label。
- 折叠行通过 inert 排除键盘焦点及读屏顺序，展开恢复；值仍保留用于查询。
- 删除 CRM 的 `100vh - 360px` 表格上限和地图 420–720px 限制，改为父容器 flex 分配剩余空间；分页独立占据底部，表格设置 height=100%。
- 列表压缩单元格内边距；名称与标签同排，长名称省略并提供完整 title，点击进入详情；定位与标签保留。
- 分页复用 Element Plus 的总数、页容量、上一页/下一页及页次展示。当前接口为游标分页，保留真实的顺序翻页，不伪造任意页跳转能力。
- 旧隔离验收页也移除 1280px 固定画布，用 flex 让真实组件获得可用视口。
- 窄屏导航可自动收起，也能手动展开；窄屏表格整体在容器内横向滚动，避免固定列互相遮盖；列设置使用有名称的图标按钮，分页保持一行。

## 公共约束清理

- AGENTS 中明确：设计 Token 可复用但不锁定页面尺寸/布局，历史 QA 截图不作为新设计的硬性前提。
- 历史 CRM QA 去掉作为当前依据的固定字号、24px 边距描述，标记为历史版本。
- 删除所有 Console 卡片/表格的全局固定内边距、行高、圆角与阴影覆盖；共享主题保留为低优先级颜色变量。
- 删除全站供给链公共 CSS 对说明文案、指标口径、边界提示的静默隐藏规则。
- 删除通用按钮最小宽度、控件高度、筛选背景和外观的跨页面覆盖；删除强制斑马纹以及宽度/悬浮/阴影上的 `!important`。
- 修复外壳 28px padding 覆盖供应链响应式 padding 的冲突。
- 删除移动端公共列表的固定 360px 表体、销售页 980px 最小高度；保留必要的视口、滚动、组件本身尺寸和显式复用布局。
- 公共样式目录已无 `!important`，无通过 `display:none` 隐藏业务文案的规则。页面自己的权限隐藏、折叠交互及必要响应式规则不属于这类清理。

## 验证证据

- 真实 DEV 登录页面验证，沿用用户运行的 Vite 与后端服务，未新建后台进程。
- 1440×900：列表、展开筛选、地图聚焦、真实查询空结果及重置正常；页脚 bottom=885，留出底部边距。
- 列表正文 scrollTop 从 0 到 127 时，标题 y=84、表头 y=175、页脚 y=836 均不变。
- 地图 1440×900：地图画布与正文区域均为 1110×617，紧接底部分页，无任意固定高度上限。
- 768×1024、390×844：侧栏收起，页面无横向溢出；手机页脚高 49px、bottom=833，地图高 506.5px，内容容器 clientHeight=scrollHeight=774。
- 真实查询不存在的门店后显示 0 条；重置回 11 条，空结果时分页位置不变。
- 抽查订单列表、旧客户档案、销售管控台：页面未溢出，筛选/表格/分页可用；销售短屏 1440×680 的指标说明仍可见。
- 9 个相关测试文件共 70 项通过，覆盖 CRM 列表/地图、游标翻页、空结果、筛选折叠可访问性、侧栏响应式与释放监听、页签缓存、订单及旧客户查询。
- 定向 ESLint、vue-tsc、生产构建、git diff --check 通过；构建仍有已有依赖注释与大包提示。
- taste 静态检查：0 FAIL、11 WARN。保留品牌蓝；破折号表示缺失数据；地图卡片/标记属于浮层，阴影有用途，`box-shadow:none` 为检查器误报。
- 实际浏览器通过 CUA 进行截图和 DOM 尺寸核验；未运行会另起浏览器的 inspect.mjs，不宣称其自动检查通过。未做全站每个业务页面的逐项验收。
