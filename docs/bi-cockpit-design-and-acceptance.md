# BI 驾驶舱设计与验收

更新日期：2026-09-11。范围：Portal 现有供应链 BI，沿用 Gateway / Analytics BI 契约和权限，不修改业务事实、不写入演示成本。

## 已确认的需求基线

- 可视化优先：统一分析画布、紧凑指标、趋势/排行/结构/进度/异常图表；主页面不再堆叠业务表、角色卡片、能力说明卡片。
- 总览前置销售额、回款额、待回款、回款率，必须同时保留经营成本和经营结余。
- 数据已有支持时使用真实 BI 响应；成本分类、SKU损耗、活动尚无事实时使用独立样例。只在受影响的指标、图表、明细和导出标样例。
- 保留城市、销售、客户、分类、商品、SKU维度。不同角色是验收视角，不是总览中的角色列表。
- 货：货品、运费、损耗；人：底薪绩效、提成、激励、兼职；场：仓储、办公室租金、营销费。
- 同时保留货品、物流、仓库、人力、房租和其他补充项的分类映射，营销包含试吃、活动；人力只有汇总，不输出个人薪资。
- SKU样例保留方便面/粉菜面蛋/干拌面、口味、规格、水类、台泥、采购价、数量及损耗率。不是把价格表零售价当作真实采购成本。

## 页面与工作问题

| 页面 | 可视化 | 支持的工作判断与入口 |
| --- | --- | --- |
| 经营总览 | 销售/已收趋势、简洁回款仪表、成本瀑布、城市回款构成、账龄、分类贡献 | 老板判断规模、现金回收、成本与结余；进入城市、销售、回款专题 |
| 销售监控 | 月度销售Top6分组柱、目标热力、已回款/待回款纵向堆叠柱及百分比 | 销售总比较人员贡献、回款差距、目标达成；按待回款优先分页，明细保留销售归属 |
| 销售与回款 | 订单归期趋势、回款进度、按发生日期的回款趋势、账龄 | 区分同批订单累计回款与期间实际收款；回款单据入口 |
| 城市经营 | 城市回款纵向堆叠柱、账龄、收入成本对比、目标、人员回款/分类贡献 | 城市负责人从城市定位销售/品类差异；保留城市筛选下钻 |
| 客户经营 | 客户分层构成、贡献/待回款、价值活跃度散点、未下单天数 | 运营识别高价值客户、回访对象、责任销售；客户资料入口 |
| 商品销售 | 商品/SKU/分类/品牌贡献、客户覆盖 | 运营与销售判断品类、规格、客户覆盖；具体商品订单入口 |
| 销售毛利 | 参考采购价成本/毛利、采购价覆盖、低毛利、退款 | 先识别采购价覆盖缺口，再看覆盖完整的商品毛利；不是净利润 |
| 采购与库存 | 采购/发货/留存、可售天数、可用/在途/建议量、历史留存 | 按计量单位分别查看；库存缺失时只保留真实销售需求，不给伪补货量 |
| 回款风险 | 城市/责任销售逾期金额、账龄、城市回款构成及百分比 | 区分逾期风险与回款比例；定位城市和销售，查看订单 |
| 成本与盈亏 | 盈亏瀑布、货人场堆叠、城市收入成本、成本项、SKU采购损耗、人力构成 | 保留完整会议成本结构，样例明确；个人薪资不进入页面 |
| 库存风险 | 重点风险等级、异常类型、补货对比 | 只统计接口返回的重点项；库存快照缺失不显示“0风险” |
| 活动经营 | 销售投入、转化、预算执行、费用产出比 | 独立活动样例，不混入真实经营销售；不把费用产出比叫净利润ROI |

销售与回款仍保留原有独立路由模型。当前IAM导航未授权独立回款路由时，通过已授权销售页内的“回款”视图使用相同BI契约；不修改或绕过权限守卫。

## 数据约束

- 销售与累计回款来自订单事实；期间回款来自回款事实，不能互相替代。
- 使用现有接口的UTC日期约定；月度下钻与当前筛选日期取交集，不扩大到未选择的整月。
- 未配置目标、零分母、缺失指标显示空值；已有零成本记录不能被样例覆盖。
- 目标达成按实际值合计/目标合计，不平均各人百分比。
- 月趋势合计接口实际记录；中间缺失月份保留空值，不伪造零或趋势。
- 金额指标/坐标轴允许万元缩写；明细和CSV保留元和两位小数，保留样例标签。
- 成本城市总额优先使用 `cityCostRanking.recordCount > 0` 的事实。缺失城市以销售额57%的演示假设补位，派生结余同时标样例；该比例不是测算结论。
- 接口尚未提供成本分项事实，货人场比例、SKU采购损耗均仍是样例，不能因城市总额真实就把分项标成真实。
- ERP参考价毛利只有采购价完整覆盖时才展示总体毛利；不把缺采购价按零造成的高毛利作为结论。
- 库存快照明确EMPTY时不显示安全零风险、不生成补货行动，保留实际日均销售需求供查看。箱、瓶、桶不能直接合计。
- `9999` 无历史订单哨兵不显示为“9999天未下单”，使用“尚未下单/首单跟进”。
- 自动刷新只刷新已应用条件；请求序号防止旧响应覆盖新筛选，失败不保留旧数字伪装成功。
- 页面时间标为查询时间。各来源更新时间、水位和核对内容在信息抽屉，不能用对账任务时间冒充业务数据更新时间。

## 交互边界

- 图表明细通过图形点击或标题旁按钮进入抽屉，支持搜索、分页、CSV导出；表格仅在明细/治理抽屉。
- 成本分组、目标维度、库存异常分组的点击保留分组筛选。
- 总览/专题行动使用已有回款风险、客户活动、库存建议事实；样例不触发业务写操作。
- 订单页面目前只能承接日期、城市、销售、具体商品/SKU条件。分类、客户类型、来源无法完整传递时给出提示，不能宣称跳转结果与看板完全同口径。
- 当前目标配置页面尚未开放，因此提供真实配置缺口导出，不能以跳到未开放页面冒充目标闭环。
- 60秒自动刷新可关闭，离开页面清理计时器；大屏模式可退出。

## 尚未验收通过

1. 来源→业务的订单/回款DIFF尚未逐条解释消除，不能宣称数据全链路已对账通过。
2. 真实成本分类/SKU损耗/人事薪酬绩效/活动归因事实尚未接入；样例保留用于结构确认。
3. 催收状态、下次跟进时间、责任任务写回没有形成业务闭环；当前仅定位对象并进入已有业务页面。
4. 目标配置与HR绩效录入页面尚未实现，已有目标可视化不等于HR模块完工。
5. 当前源库存与采购流转为空，需要确认实际ERP台账及同步范围后再验收补货建议。
6. 下钻到各领域页面的全角色权限、筛选完全对等、完整键盘路径/读屏/颜色对比仍需补充验收；本次未宣称WCAG通过。

结论：驾驶舱可视化重构及上述数据保护已实现，不能把这份局部验收写成“生产全链路已验收通过”。
