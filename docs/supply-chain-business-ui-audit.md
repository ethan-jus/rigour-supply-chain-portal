# 供应链业务前端展示与功能审计

> 审计快照：2026-08-17，分支 `feature/sync-reconciliation-repair`。范围为 Portal 供应链路由、已实现页面、通用占位页及其直接消费的 Platform API DTO/IAM 资源。本文中的“已确认”来自当前源码；“建议”是待实施目标，不代表线上已具备。

## 结论与边界

当前问题不只是样式：部分普通业务详情接口直接返回了原始报文、来源字段、内部状态、完整银行/税号/联系方式等字段。仅在 Vue 模板中不渲染，不能构成安全控制；浏览器网络响应、导出、日志和其他客户端仍可能取得这些数据。

审计遵循以下边界：

- 业务页面保留业务编码、名称、业务状态、数量、已授权金额和必要履约信息。
- 默认不展示数据库 UUID、订货宝来源 ID、任务/批次/游标 ID、`internalStatus`、`ownershipState`、版本号、Raw JSON、`sourceFields`、`payloadHash`、Secret 引用和技术错误栈。
- 手机、邮箱、详细地址、银行账号、纳税人识别号、精确轨迹、录音/照片按“最小展示 + 单独能力 + 数据范围 + 查看审计”处理；列表默认脱敏，详情按需揭示。
- 采购价、成本价、应收应付、交易账户等不是通用“读权限”的附属字段，必须单独按采购/成本/财务角色授权。
- 订货宝对象在一次增量同步中未出现，不能据此判断已删除。只有成功完成且对账通过的权威 `FULL`/`REPAIR` 全量快照，才能将本地保留数据标识为“来源已不存在”；分页失败、超时或部分响应不得改变存在性状态。

### 3. 业务字典第一阶段降噪

`BusinessDictionaryView.vue` 已完成第一阶段前端收口：

- 文案从平台治理术语改为业务核对语言，新增名称/编码快速查找。

## 二、应保留，但必须按角色控制

| 角色 | 应保留的业务能力 | 默认不得展示/操作 |
| --- | --- | --- |
| 普通业务人员 | 客户/商品/订单的业务编号、名称、业务状态、本人数据范围内的数量与履约摘要 | 集成后台、Raw/Hash、来源 ID、内部状态、完整联系方式、银行税号、成本价、精确位置、字典治理 |
| 采购/仓储人员 | 供应商名称、采购/退货/入库单、仓库、数量、采购业务状态；按职责查看必要采购价格 | 银行账户/税号、连接器信息、任意付款执行、无关仓库/城市数据 |
| 财务/供应商主数据专员 | 应收应付、付款资料、银行/税务字段的按需揭示和供应商资料维护 | 连接器 Secret/Raw、超出数据范围的客户与供应商、平台字典治理 |
| 经营管理者 | 汇总指标、团队/城市下钻、业务异常摘要 | 原始技术错误、Raw 数据、全量敏感明细导出、未经授权的精确位置/录音 |
| 销售主管/复核人 | 拜访计划、复核队列、证据摘要；必要时按能力查看照片/录音/轨迹 | 任意跨团队查看、后台直链、未经审计的媒体/轨迹下载 |
| 集成/数据运维 | 连接、任务、映射、重试、对账、来源存在性和脱敏日志 | 真实 Secret 值、无关业务 PII；技术权限不得隐式获得财务/客户全量权限 |
| 租户业务配置管理员 | 服务端明确标注“租户可编辑”的业务选项：显示名称、是否可选、显示顺序 | 系统/模块作用域、租户 UUID、基础字典 ID、任意扩展 JSON、来源原值写入 |
| 平台数据治理 | 模块/作用域/继承/版本/影响范围/审计差异；受控代租户支持 | 无审计的跨租户修改、直接输入任意租户 UUID、修改来源系统拥有字段 |

所有角色还必须叠加租户和 DataScope。页面按钮的 `v-if` 只改善体验，最终授权必须在 Gateway/领域服务端校验；不能把“菜单不可见”当作接口安全。

## 三、后续必须由后端收口

### P0：普通业务 DTO 不得携带 Raw/来源原文

已确认存在以下直接暴露面：

- 订单详情 `DhbOrderDetailView` 包含 `sourceRecords`，其中 `DhbOrderSourceRecordView` 含 `payloadJson`、`payloadHash`；Portal 的 `src/api/dhb.ts` 同样公开这些字段。
- CRM `CustomerDetailView`、`AddressView` 及 Portal `src/api/core/crm.ts` 含 `sourceFields`、来源 GUID/ID、来源更新时间。
- ERP `PurchaseOrderDetailView`/`PurchaseOrderLineView`、`PurchaseReturnDetailView`/明细、`WarehousingReceiptDetailView`/明细及 Portal `src/api/core/erp-supply.ts` 含 `sourceFields`。

执行要求：

1. 从普通列表/详情 DTO 中删除 `sourceRecords`、`payloadJson`、`payloadHash`、`sourceFields`，不是只在前端隐藏。
2. 如确需诊断，建立独立的管理端诊断 DTO/端点，绑定 `*:source-audit:read`，限制 DataScope，记录查看审计，并对日志/原文二次脱敏。
3. 禁止 Raw JSON 进入普通导出、浏览器缓存、埋点、错误提示和前端日志。

### P0：PII、银行税务、成本财务必须服务端投影

- 列表 DTO 直接返回脱敏后的手机、邮箱、地址、银行账号、税号；不要让前端拿到完整值后再替换星号。
- 详情揭示使用独立能力，例如 `crm:customer:pii:read`、`erp:supplier:sensitive:read`、`order:finance:read`、`erp:cost:read`，并记录查看原因、操作者、对象和时间。
- 通用 `crm:customer:read`、`erp:product:read`、`erp:supply:read`、`order:read` 不应自动获得完整敏感字段、采购价或财务账户。
- 导出使用同一字段投影规则，禁止导出绕过页面脱敏。

### P0：来源删除状态必须可证据化

业务端只展示稳定业务标签：

| 服务端状态 | 业务文案 | 使用规则 |
| --- | --- | --- |
| `UNKNOWN` | 待完成全量核对 | 历史数据或尚无成功完整快照，不得伪装“有效” |
| `PRESENT` | 来源有效 | 最近一次成功且完整的权威核对中存在 |
| `ABSENT_CANDIDATE` | 待核对 | CRM 首次完整快照未见，尚未达到连续两次确认条件 |
| `SOURCE_ABSENT` / `ABSENT` / `DELETED` | 来源已删除（本地保留） | 仅权威完整快照达到领域确认条件后设置，不物理删除本地业务记录 |

列表应支持 `sourcePresence` 服务端筛选。普通业务人员不需要看到 `lastSeenRunId`、游标、Payload Hash；数据运维可在独立对账页查看 run、期望数、Raw 数、主/明细数、失败数和修复结果。

### P1：操作权限和深链路必须一致

已确认 `routes.ts` 中大量订单、销售、ERP、集成路由只有 `requiresAuth`/`applicationCode`，未声明页面能力；订单页“同步”按钮必须同时按后端现行的 `integration:dhb:read` 与 `integration:dhb:write` 做前端隐藏，不能继续使用 IAM V16 已删除的 `order:write`。需要：

- IAM 页面资源决定导航可见性；前端 route meta/按钮能力用于失败前提示；Gateway/领域服务负责最终强制授权，三处使用同一能力编码。
- 同步、重试、映射、连接测试、创建/编辑/审批/付款、敏感查看、导出分别授权，禁止一个 `write` 覆盖所有高风险操作。
- 对未实现页面，默认不向普通业务角色发放 PAGE；用户明确要求保留的“采购付款单”是当前例外，但仍不能提供假数据或可提交按钮。

### P1：未接入能力不得伪装成可用控件

空态本身可以保留，但看起来可点击的按钮、链接、下拉和快捷入口必须具备真实行为，或以 disabled 状态明确标注“建设中”。`href="#"`、无事件处理器的按钮、静态下拉箭头和没有目标的快捷操作会让业务人员误以为系统故障，也会产生错误培训口径。

### P1：筛选必须由服务端完成

当前部分页面只有关键词或自由文本状态，若只对当前分页结果做客户端过滤，会产生漏数和错误合计。所有新增筛选须进入 API 查询参数、数据库索引和总数统计，并在服务端应用租户/DataScope；枚举字段使用字典选择器，避免自由文本。

### P1：字典治理 API 拆分

需要将“业务运行时查字典”“租户业务选项配置”“来源映射治理”“平台字典治理”拆成不同端点和权限；详见字典专项。后端必须校验作用域、当前租户、可编辑字段、唯一性、引用影响和乐观锁，不能依赖前端 `canEditDict`。

来源存在性也必须区分两类数据：ERP 分类、品牌、规格、标签以及 CRM 客户类型、地区等是可通过完整主数据快照核对的来源字典，可以展示来源删除状态；标签分组目前只从标签响应派生，没有独立的权威分组目录，无标签的有效空分组不能判删除，只能保持“待核对”。公共 `DHB_*` 状态、类型、单位翻译项只是从业务记录观察到的映射，并非订货宝权威枚举目录。某个值未在本轮订单或商品中出现，不代表来源已删除，当前只能保留为“待核对/最近观察”，不得自动改成 `SOURCE_ABSENT` 或 `DISABLED`。只有后续接入带生产者、租户、批次和完整快照证明的权威枚举目录，才可对自动生成项建立独立来源存在性台账。

## 四、逐主要页面审计

### 供应链首页

证据：供应链首页复用 `src/components/console/ConsoleDashboard.vue`。其中四个指标均为 `—` 和“等待服务接入”；“近30天订单趋势”只有静态空图，“近30天⌄”按钮没有选择逻辑；“查看全部”是 `href="#"`；“新建订单/新增客户/邀请成员/数据报表”快捷按钮没有点击行为。“实时权限”的绿色状态也只来自静态文案，不能证明业务数据实时。

- 这是高影响的误导性 affordance：它位于普通业务人员的首屏，外观上可操作，实际无数据/无跳转。
- 在真实聚合 API、目标路由和权限准备前，移除这些控件或整体标为“工作台建设中”；如果保留按钮，必须 disabled 并说明缺失能力，不能用可点击样式。
- 接入后，周期按钮必须真实改变服务端查询范围，“查看全部”和快捷操作必须有授权目标；无权限操作不展示。

### ERP 商品与主数据

证据：`ProductMasterDataView.vue` 和 `src/api/core/erp-product.ts` 当前包含来源 ID、本地记录 ID、`internalStatus`、`ownershipState`、来源排序/时间、采购价等字段，并在列表/抽屉多处展示内部状态和“数据主权”。

- 保留：SPU/SKU 编码与名称、品牌、分类、规格、单位、条码、业务上架状态；市场/订货价格按业务需要展示。
- 隐藏：数据库/来源 ID、`internalStatus`、`ownershipState`、版本、来源排序、同步时间和“来源信息”技术页签。
- 受控：采购价/成本价只给采购或成本角色。
- 当前可用筛选必须按接口逐页拆开：商品只支持 SPU 编码、商品名称或默认条码综合查询，SKU 只支持 SKU 编码、条码、所属 SPU 编码或商品名称综合查询；商品/SKU 另有独立上架状态。分类、品牌、规格、标签页只支持各自编码或名称。品牌、分类、规格不能伪装成商品/SKU 列表的独立条件，价格区间、缺价和低库存也必须等后端扩参后再启用。

### ERP 供应商、采购、入库与库存

证据：`SupplyDataView.vue`/`src/api/core/erp-supply.ts` 展示或承载 `sourceSupplierId`、`sourceWarehouseId`、来源单据/明细 ID、完整手机号/邮箱/地址、银行账号、税号、`internalCommunication`、API/下载状态、采购价/单位成本/批发价和 `sourceFields`。

- 供应商：列表只展示脱敏联系人；银行账号、税号、完整联系方式仅供应商主数据/财务角色按需揭示。
- 采购/退货/入库：保留业务单号、供应商、仓库、业务状态、数量和授权金额；隐藏来源 ID、内部通信、下载/API 状态、原始字段。
- 库存：保留商品、SKU、仓库、可用/占用/在途等业务数量；不要显示主权/内部同步状态。
- 当前可用筛选按页面区分：供应商支持编码/名称/联系人综合查询；采购单支持单号、供应商编码/名称、仓库综合查询和来源业务状态；采购退货支持退货号、供应商编码/名称、退货原因综合查询和来源业务状态；入库单支持入库号、仓库、供应商、入库类型综合查询和来源业务状态；仓库支持编码/名称/地址综合查询；库存支持商品编码/名称/规格综合查询、仓库多选和可用库存状态。单据日期、付款状态、金额、分类、品牌和低库存等独立条件需后端扩参后再增加。
- 来源存在性：供应商、采购单、采购退货、入库单、仓库可由完整来源快照核对；库存按当前有效商品编码分批查询，缺少全局稳定键集合且上游可能省略零库存，未返回不能推断删除，只能保持“待核对”。

### CRM 客户、地址、归属与外部员工

证据：`CrmMasterDataView.vue`/`src/api/core/crm.ts` 当前展示或承载登录账号、完整手机/邮箱/地址、次要归属来源员工 ID、客户/地区 GUID、`internalStatus`、来源时间和 `sourceFields`。

- 保留：客户编码/名称、业务来源状态、客户类型、地区、主销售/团队和有效归属。
- 默认脱敏：手机、邮箱、详细地址；列表不展示登录账号。
- 隐藏：数据库/来源 GUID/ID、CRM `internalStatus`、同步时间、归属技术 ID。
- 当前可用筛选按接口区分：客户档案支持客户编号/名称综合查询和客户内部业务状态；地址支持客户编号/名称、收货人、联系人、电话、地区及地址综合查询；客户类型、地区只支持编码或名称；外部员工只支持员工来源编号、账号名或姓名，其中业务界面不宣传已隐藏的账号字段。客户类型、地区、主销售/团队、地址默认状态、组织、手机号等独立条件必须等后端扩参并完成权限设计后再增加。

### 订单、履约、退货与收付

证据：`Order/IndexView.vue` 当前展示完整收货电话、供应商同步/接口状态、同步异常；详情包含来源更新时间、客户 GUID、操作审计姓名、完整电话/地址、内部备注、税号/银行、采购价、交易流水和账户信息。`src/api/dhb.ts` 还承载未渲染的完整 Raw 记录。

- 业务列表保留订单号、客户、销售、订单/付款/履约状态、金额和仓库/物流摘要。
- “接口状态/同步异常/来源更新时间”移入集成运维对账页；业务人员只看可行动的业务异常。
- 手机/地址脱敏；税号/银行/交易账户按财务能力揭示；采购价按成本能力揭示。
- “同步”按钮仅数据运维或明确授权角色可用，并由服务端校验、限流和审计。
- 当前订单主列表支持关键词（订单号、客户、收货信息和备注）、订单状态、来源状态、下单日期、收款状态；来源异常菜单使用后端 `sourcePresence=SOURCE_ABSENT` 查询，不再复用同步异常参数。异常订单页可以继续组合订单状态和收款状态。发货、物流、退货支持单据状态、精确订单号和对应业务日期，收付款页支持单据状态、精确订单号和交易日期。销售、城市、仓库、金额、付款方式和差异状态等独立条件尚无对应参数，不得做当前页假筛选。

### 外部集成与订货宝工作台

证据：`DhbPage.vue` 包含 connector code、Base URL、Secret reference、task code、对象类型、调度、来源订单 ID、镜像状态、错误消息、字段映射及连接测试/任务执行等写操作；路由未声明独立页面权限。

另有已确认的名称/能力不一致：路由“原始数据查询”实际映射 `pageKey=order-mirror`，只读取订单镜像，不是 Raw Landing 查询；“重试与死信”实际映射 `sync-logs`，只展示日志，没有重试、死信队列或重放动作；“数据对账”与“主权与切换状态”分别落到 `data-quality`/`bi-prep` 通用空态，仅显示规则/BI 输出建议，并无真实对账或切换能力。

- 整个模块默认只给集成/数据运维，不进入普通业务菜单。
- 菜单名称必须与真实能力一致：当前可改名为“订单镜像”“同步日志”，或在真正实现 Raw 查询、死信队列/重试后再恢复现名；`data-quality`/`bi-prep` 在接入真实 API 前不授权普通角色并明确标注占位。
- 业务管理者如需了解质量，只给脱敏“同步质量摘要”：业务对象、最后成功时间、待核对/来源不存在/失败数量和对账结论，不显示连接器/任务/Raw/错误栈。
- Secret 值永不返回；Secret reference 也不对普通业务展示。配置时应从受控 Secret 别名中选择，不能自由输入秘密或别名。
- 服务端清洗日志消息，避免上游响应、URL 查询参数、手机号/地址或凭据进入错误文本。
- 管理筛选：连接器/对象类型、任务、运行时间、运行结果、差异类型、是否可修复；分页与统计全部服务端完成。

### 销售管控台

证据：`SalesDashboard.vue` 以团队/人员业务汇总为主，风险较低；当前主要筛选集中在日期范围。

- 保留：本人/授权团队的拜访、覆盖、证据异常、复核任务汇总。
- 筛选：日期、团队、城市、销售人员；数据范围由服务端强制。
- 聚合异常只能提示风险，不能自动认定违规或直接影响薪资。

### 拜访计划

证据：`SalesVisitPlans.vue` 列表和门店选择包含详细地址，新增/编辑/取消操作未见前端能力判断。

- 地址列表最小化到区域/道路摘要；完整地址只给计划执行需要的角色。
- 写操作绑定 `sales:visit-plan:write`，服务端继续强制权限和 DataScope。
- 筛选：销售/团队/城市、门店/客户、计划状态、日期范围。

### 拜访复核、照片、录音与轨迹

证据：`SalesReviewQueue.vue` 已采用“授权查看/播放”并释放 object URL，这是正确方向；但人员、门店、结果说明、照片/录音元数据仍属敏感。轨迹页展示精确路线，属于高敏位置数据。

- 队列仅销售主管/复核角色；照片、录音、精确位置分别使用独立能力，查看全程审计，媒体 URL 短时有效且不可持久化。
- 轨迹限制日期跨度和本人 DataScope，不提供原始坐标表或通用导出。
- 筛选：团队/城市/销售、门店、异常类型、证据缺口、意向/复核状态和日期。

### 业务字典

证据：`BusinessDictionaryView.vue` 同时承载系统/模块/租户作用域、模块编码、字典编码、租户 ID、基础字典 ID、来源原值和 `extraJson`；来源归属通过 `DHB_` 前缀推断；写权限仅为通用 `business-settings:dict:write`。

处置方案见下一节。普通业务人员不应进入治理页面，只消费有效字典名称。

### 城市运营、BI、人事、渠道代理及其他通用占位页

证据：`SUPPLY_DOMAIN_PAGES` 当前共 80 个领域页面，其中只有 6 个 ERP 商品、7 个 ERP 供应链、5 个 CRM 和 1 个业务字典路由接入对应真实组件，其余 61 个使用 `CapabilityView.vue` 通用占位。销售目录也有大量页面只显示定义中的 owner/API/facts，尚无真实业务组件。

- 未接入真实 API、权限、筛选和空态验收的页面，默认不向普通业务角色发放 IAM PAGE。
- 通用占位页不得展示服务名、API 路径、routeKey、待建技术边界等实现细节；对业务只显示“能力建设中”和明确的不可操作状态。
- 采购付款单是本轮按明确需求保留的占位例外，已使用专用业务文案且不生成假数据。

## 五、业务字典专项整改

### 目标分层

1. **业务运行时查询**：所有业务页面只调用 lookup/resolve，取得编码、显示名称、排序和有效状态；权限应为轻量 `business-settings:dict:lookup`，不返回治理元数据。
2. **租户业务选项配置**：仅租户配置管理员可维护后端白名单标记为 `tenantEditable` 的字典；页面字段只有“显示名称、是否可选、显示顺序”。
3. **订货宝来源映射**：独立的待映射队列，展示“来源值 → 业务显示名称、映射状态、版本”；来源值不可编辑，不允许创建任意字典/字典项。
4. **平台字典治理**：仅平台数据治理角色可管理模块、作用域、基础字典、schema、版本、影响范围和审计差异；代租户操作必须选择公司/租户编码并记录原因。

### 必须直接实施的项

- 后端增加 `managedBy`/`editableFields`/`tenantEditable` 元数据，替代 `code.startsWith('DHB_')` 前缀判断。
- 前端模块下拉与服务端目录枚举使用同一白名单；后端拒绝白名单外字符串，并校验模块/字典编码唯一性和保留前缀，不能因 UI 已下拉而信任请求体。
- 租户管理员只能操作当前租户的 TENANT 字典；平台代管使用受控租户选择器，禁止自由输入租户 UUID。
- `extraJson` 替换为有类型字段。确实无法移除时，仅平台治理可见，并执行 JSON Schema、大小限制、允许键名单和敏感键黑名单校验。
- 来源同步拥有的原值、编码和来源标识不可编辑；业务映射员只能修改显示名称/映射状态。
- 分类、品牌、规格、标签、客户类型、地区等权威来源主数据可以显示“来源有效/待核对/来源已删除（本地保留）”；从普通业务记录观察生成的状态、类型、单位映射不得用“本轮未出现”推断删除，也不得联动治理状态 `DISABLED`。
- 启停/删除前返回引用数量和影响页面；有引用时禁止破坏性删除，采用停用和替代项迁移。
- 返回 revision、修改人/时间、影响数量；保存使用乐观锁，展示字段级 diff，并写入审计日志。
- 将 `dict:lookup`、租户配置写、来源映射写、平台治理读写拆分为不同能力，停止用一个 `dict:write` 覆盖全部场景。

### 字典筛选

- 普通租户配置：业务名称、业务模块（下拉）、启用状态、是否有待映射项。
- 来源映射员：来源系统、业务对象、已映射/未映射/冲突、首次/最近出现时间。
- 平台治理：模块、作用域、租户（公司名/编码选择器）、管理来源、版本、启停状态、引用情况。
